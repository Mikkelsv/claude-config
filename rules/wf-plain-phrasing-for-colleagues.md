# Plain Phrasing for Colleagues

When drafting text the user will send to a colleague, such as a Slack message, PR comment, email, ticket update, or review reply, write it tight, plain, and specific.

## Always do

- **Short.** As few sentences as the point needs. No preamble, no padding.
- **Plain words.** Everyday vocabulary. No "leverage", "surface", "align on", "delta", "cadence", "circle back".
- **Name the thing.** Spell out the file, branch, PR number, error text, or decision. The reader does not have the user's context and cannot act on "that thing we discussed" or "the fix".
- **No formatting.** Plain sentences only. No bold, no italics, no headings, no markdown links, no bullet lists unless the content is genuinely a list of three or more items.
- **No em-dashes.** Use a period, a comma, or a colon.
- **No long comma chains.** One clause per sentence. Break instead of stacking.
- **Few parentheses.** If the aside matters, make it its own sentence. If it does not, cut it.
- **Avoid colon-introduced lists.** Write the items into the sentence instead.

## Why

Suggested phrasing gets pasted as-is. The default LLM register is long, hedged, em-dash heavy, and over-formatted, which reads as AI-written and buries the actual ask. Vague references force a follow-up question, so the message costs two round-trips.

## How to check

Read it back. Can the colleague act on it without asking a clarifying question? Anything you would not say out loud, cut.

## Exceptions

- User asks for a formal or long-form draft, such as a customer-facing doc, spec, or incident write-up.
- User asks to match an existing tone or template.

Tier: always do.
